# Interacting with the Enterprise Data Catalog

You can interact with the Enterprise Data Catalog not only using the UI, but also using APIs or CLI. The CLI is integrated with the Securiti solution using the EDC ingestion, The other way is to install the CLI on your machine having network connectivity to perform supported operations using CLI from your machine. For example, loading metadata for sources supported by the community and not supported by Securiti connectors.

### Integration options

The Enterprise Data Catalog can be supplied with metadata from:

| Integration option | Description |
| --- | --- |
| Sensitive Data Intelligence scans | These scans supply the catalog with metadata and classification (tags) information for structured, unstructured (CSV and JSON file formats), and streaming sources (topics). |
| Structured and streaming data explorer | You can manually select structured and streaming datasets from their respective explorer and supply the catalog with metadata classification (tags) information. |
| DataHub project (DH) plugins | - These plugins are developed by the DH community. - Execution is done using DHs CLI that can be installed in any machine with network connectivity to the source and the Enterprise Data Catalog. - Depending on the source, these plugins can provide not just metadata but also lineage, profiling and usage. - You can also run the provided DH plugins using [EDC ingestion](/v1/docs/edc-settings). |
| DataHub graphQL | Lets you interact (Read=Queries, Update=Mutations) with the entities and relationships in the metadata graph. The UI is based on this, meaning that anything displayed in the UI can be retrieved using GraphQL. |
| DataHub RESTAPIs | You can also ingest metadata using DH RESTAPIs using the [Rest.li.framework](https://docs-website-2uuxmgza2-acryldata.vercel.app/docs/api/restli/restli-overview). |

### GraphQL API

> [!NOTE]
> **Note**
> 
> You need to access the Enterprise Data Catalog first to be authenticated.

The GraphQL API lets you query the catalogs data graph. This provides a rich GraphQL API for programmatically interacting with the entities and relationships comprising your organization's metadata graph.

The GraphQL API can be accessed at: https://edc.app.securiti.ai/api/graphiql.

> [!NOTE]
> **Note**
> 
> The Enterprise Data Catalog UI is based on GraphQL, this means that everything in the UI can be queried with it. You can see the payloads by looking into the browser’s network tab under developer tools.

For more information, read [Enterprise Data Catalog API reference](https://securiti-doc-router.securiti.ai/modules/data-catalog/apidocs/index.html)

### DataHub CLI

DataHub comes with a friendly CLI. The Enterprise Data Catalog fully supports this CLI and lets you perform a lot of common operations using just the command line. Note that EDC is compatible with CLI version 0.12.1.5.

This includes the creation, update, deletion of various objects within the data catalog. It also lets you push the lineage, usage, and profiling generated by the plugins. These plugins extract lineage, usage, profiling, and other metadata from the sources listed below and load them into the Enterprise Data Catalog.

#### CLI installation guide

To install CLI:

1. Follow the instructions under DataHub CLI.

> [!NOTE]
> **Note**
> 
> We do not need to install a local version of DH. We will use the CLI in conjunction with the Enterprise Data Catalog.
2. Create your Securiti Token so you can connect to the Enterprise Data Catalog.
3. After you authenticate to the Securiti environment go to:
  - https://app.securiti.ai/privaci/v1/admin/data_catalog/api/generate_session_token (basically <url>/privaci/v1/admin/data_catalog/api/generate_session_token).
  - Extract the content of **accessToken** from the response.
4. Configure your **Env Variables** to connect.

> [!NOTE]
> **Note**
> 
> If you are working with multiple tenants at the same time, make sure that you are using the correct token. The token will direct the CLI actions to that tenant. See executing plugins for more information on executing plugins.

#### Supported environment variables

The env variables take precedence over what is in the DataHub CLI config created through **init** command.

> [!NOTE]
> **Note**
> 
> The init command is used to tell datahub about where your DataHub instance is located. The CLI will point to localhost DataHub by default.

The main variables to configure are:

- DATAHUB_GMS_URL
- DATAHUB_GMS_TOKEN

The **DATAHUB_GMS_URL** typically will be: https://dh.app.securiti.ai/api/gms. However, The **DATAHUB_GMS_TOKEN** is the content of the token generated from the given link: https://app.securiti.ai/privaci/v1/admin/data_catalog/api/generate_session_token

#### Recipe and its core concepts

A recipe is the main configuration file that puts it all together. It tells our ingestion scripts where to pull data from (source) and where to put it (sink).

| Recipe core concept | Description |
| --- | --- |
| Sources | Data systems that we are extracting metadata from are referred to as sources. |
| Sinks | Sinks are destinations for metadata. When configuring ingestion for DataHub, you are likely to be sending the metadata to DataHub over either the REST or the sink. |

Write the following command to run the recipe:

```yaml
datahub ingest -c lineage_non_Local.recipe.dhub.yaml
```

> [!NOTE]
> **Note**
> 
> One recipe file can only have 1 source and 1 sink. If you want multiple sources then you will need multiple recipe files.

#### Recipe example: creating lineage between 2 objects

Below is the lineage .yml file.

```yaml
version: 1
lineage:
  - entity: 
      name: mssql-4.OperationsManager.dbo.MTV_URLGenie$HttpRequest$Seed
      type: dataset
      env: PROD
      platform: mssql
    upstream:
      - entity:
          name: mssql-4.OperationsManager.dbo.MT_URLGenie$HttpRequest$Seed_Log
          type: dataset
          env: PROD
          platform: mssql
```

Below is the simple recipe that pulls metadata from datahub-lineage-file (source) and puts it into the default sink (datahub rest).

```yaml
source:  
    type: datahub-lineage-file  
    config:    
        # Coordinates    
        file: /Users/ben/Customers/CSGi/datahub/lineage_CSG.yml    
        # Whether we want to query datahub-gms for upstream data    
        preserve_upstream: false
sink:  
    type: "datahub-rest"  
    config:    
        server: ${DATAHUB_GMS_URL}    
        token: ${DATAHUB_GMS_TOKEN}
```

#### 

A token is a small piece of data, typically in the form of a string, that serves as an authentication or authorization mechanism. It is used to verify the identity of a user or application and grant access to specific resources or functions. Tokens are commonly used for security and access control in API interactions.
