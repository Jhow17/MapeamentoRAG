# Redshift Ingestion

To ingest Redshift metadata into the EDC, read the following required configurations.

### Important capabilities

| **Capability** | **Status** | **Notes** |
| --- | --- | --- |
| Data profiling | ✅ | Optionally enabled via configuration |
| Dataset usage | ✅ | Enabled by default, can be disabled via configuration `include_usage_statistics` |
| Descriptions | ✅ | Enabled by default |
| Detect deleted entities | ✅ | Enabled via stateful ingestion |

This plugin extracts the following:

- Metadata for databases, schemas, views and tables.
- Column types associated with each table.
- Table, row, and column statistics via optional SQL profiling.
- Table lineage.
- Usage statistics.

### **Prerequisites**

This source needs to access system tables that require extra permissions. To grant these permissions, please alter your EDC Redshift user the following way:

```sql
ALTER USER edc_user WITH SYSLOG ACCESS UNRESTRICTED;
GRANT SELECT ON pg_catalog.svv_table_info to edc_user;
GRANT SELECT ON pg_catalog.svl_user_info to edc_user;
```

> **Note**
> 
> Giving a user unrestricted access to system tables gives you the visibility to data generated by other users. For example, `STL_QUERY` and `STL_QUERYTEXT` contain the full text of INSERT, UPDATE, and DELETE statements.

### **Configuration options**

The following options control what the Redshift source ingests, which objects are included, and how profiling runs. A dot in a field path indicates a nested field in the YAML recipe.

#### General, lineage, and usage

| **Field** | **Type** | **Default** | **Description** |
| --- | --- | --- | --- |
| `enable_stateful_lineage_ingestion` | boolean | True | Enable stateful lineage ingestion. This will store lineage window timestamps after successful lineage ingestion. and will not run lineage ingestion for same timestamps in subsequent run. |
| `enable_stateful_profiling` | boolean | True | Enable stateful profiling. This will store profiling timestamps per dataset after successful profiling. and will not run profiling again in subsequent run if table has not been updated. |
| `enable_stateful_usage_ingestion` | boolean | True | Enable stateful lineage ingestion. This will store usage window timestamps after successful usage ingestion. and will not run usage ingestion for same timestamps in subsequent run. |
| `format_sql_queries` | boolean | False | Whether to format sql queries |
| `include_copy_lineage` | boolean | True | Whether lineage should be collected from copy commands |
| `include_operational_stats` | boolean | True | Whether to display operational stats. |
| `include_table_lineage` | boolean | True | Whether table lineage should be ingested. |
| `include_tables` | boolean | True | Whether tables should be ingested. |
| `include_top_n_queries` | boolean | True | Whether to ingest the `top_n_queries`. |
| `include_unload_lineage` | boolean | True | Whether lineage should be collected from unload commands |
| `include_usage_statistics` | boolean | False | Generate usage statistic. `email_domain` config parameter needs to be set if enabled |
| `include_views` | boolean | True | Whether views should be ingested. |
| `incremental_lineage` | boolean | True | When enabled, emits lineage as incremental to existing lineage already in the EDC. When disabled, re-states lineage on each run. |
| `match_fully_qualified_names` | boolean | False | Whether `schema_pattern` is matched against fully qualified schema name `&lt;database&gt;.&lt;schema&gt;`. |
| `top_n_queries` | integer | 10 | Number of top queries to save to each table. |

#### Profiling

| **Field** | **Type** | **Default** | **Description** |
| --- | --- | --- | --- |
| `profiling` | GEProfilingConfig | `{'enabled': False, 'operation_config': {'lower_freq_profile_enabled': False, ...}, ...}` |  |
| `profiling.enabled` | boolean | False | Whether profiling should be done. |
| `profiling.include_field_distinct_count` | boolean | True | Whether to profile for the number of distinct values for each column. |
| `profiling.include_field_max_value` | boolean | True | Whether to profile for the max value of numeric columns. |
| `profiling.include_field_mean_value` | boolean | True | Whether to profile for the mean value of numeric columns. |
| `profiling.include_field_median_value` | boolean | True | Whether to profile for the median value of numeric columns. |
| `profiling.include_field_min_value` | boolean | True | Whether to profile for the min value of numeric columns. |
| `profiling.include_field_null_count` | boolean | True | Whether to profile for the number of nulls for each column. |
| `profiling.include_field_sample_values` | boolean | True | Whether to profile for the sample values for all columns. |
| `profiling.include_field_stddev_value` | boolean | True | Whether to profile for the standard deviation of numeric columns. |
| `profiling.profile_table_level_only` | boolean | False | Whether to perform profiling at table-level only, or include column-level profiling as well. |
| `profiling.query_combiner_enabled` | boolean | True | This feature is still experimental and can be disabled if it causes issues. Reduces the total number of queries issued and speeds up profiling by dynamically combining SQL queries where possible. |
