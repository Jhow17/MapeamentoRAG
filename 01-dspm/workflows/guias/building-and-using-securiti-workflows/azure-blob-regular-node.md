# Azure Blob

Azure Blob Storage is a service provided by Microsoft as part of the Azure platform. It is designed to store large amounts of unstructured data, such as text or binary data, which can be accessed from anywhere in the world over HTTP or HTTPS. Being a globally accessible storage solution, Azure Blob serves as a repository for files that are accessed by users from multiple locations.

Azure blob node in the Workflows module allows you to directly interact with Azure blob storage and perform the following tasks:

- **List objects:** The node retrieves a list of all objects (blobs) stored within a specified Azure Blob container.
- **Upload Objects:** It facilitates the automated uploading of files to Azure Blob Storage. This is particularly useful in scenarios where data generated by other workflow steps, such as reports, logs, or data outputs from various processes, needs to be stored to Azure Blob.
- **Download Objects:** The node downloads specific objects based on their names or other identifiers from Azure Blob Storage in the workflow for processing or further analysis of stored data.

See the [node configuration section](/v1/docs/azure-blob) to understand the node's working and properties.

#### Prerequisites

You must configure the Azure Blob node with the necessary credentials to access your Azure Blob storage. See the [setting up credentials section](/v1/docs/azure-blob).

#### Example use case

As an example, let’s consider a use case where a company stores sensitive documents in Azure Blob Storage that must be kept in compliance with industry regulations. The use case involves setting up a workflow that automatically identifies files added or modified on the current day and subsequently runs a discovery scan on these files to detect sensitive information and ensure compliance.

The workflow begins with the **Azure Blob node** configured to connect to a specific container in Azure Blob Storage. It lists all files in the container and retrieves metadata for each file, including the last modified date. An **IF node** then analyzes the list of files and their metadata. It filters out the files whose last modified date matches the current date. This step ensures that only newly added or updated files are processed further. For each file identified in the previous step as being modified or added on the current day, the discovery scan node initiates a scan. This scan is designed to detect any sensitive or regulated data update.

The following nodes are used in this use case:

1. Azure Blob Node
2. IF Node
3. Discovery Scan Node

#### Node configurations

| Parameters |
| --- |
| Azure Credentials | Select the Azure credentials to connect to the data system from the menu. If you do not have any credentials set up, refer to the [setting up credentials section](/v1/docs/azure-blob) to understand how to do it. |
| Authentication | Specify the way to authenticate to connect to Azure Blob. |
| Operation | Specify the operation to be performed using the node. |
| Upload | Choose this operation to upload object(s) to Azure Blob. |
| Download | Choose this operation to download a specific object from Azure Blob. |
| List | Choose this operation to list the objects uploaded on Azure Blob. |
| Container | Specify the container name to perform the operation on. |
| Prefix | Specify the path of the object location, for example if the prefix field has Workflow in it, then all the objects containing Workflow in the path will be fetched. |
| Object Name | Specify the object name to upload or download. |
| Property Name | Specify the name of the binary property to which to write the data of the read file, for example, data. |
| Continuous Operation | Enable this toggle to make the operation continuous for the list operation. - If toggle is disabled, the node iterates through all objects one time with page limit of 10k, e.g first iteration iterates through the first 10k, then the next 10k and so on. It finishes executing when all objects are processed. - If toggle is enabled the node iterates in loop such that, in 1st cycle it iterates over all objects as described above and then after finishing the first cycle, it starts the execution again from the 1st element and so on. |

#### Setting up credentials

Use the following configurations to set up credentials for Azure Blob.

| Parameters |
| --- |
| Credentials Name | Provide a valid name of the credentials. Use a name that makes it clear to what exactly the access is given. For example, for credentials of an email account, the name can be the email address itself. |
| Account Name | Specify the account name for shared access token or secret account key based authentications. |
| Shared Access Token | Specify the shared access token collected from Azure Blob console for shared access token based authentication. |
| Connection String | Specify the connection string for connection string based authentication. |
| Secret Account Key | Specify the secret account key, for Azure key based authentication. |
