# Sensitive Data Intelligence Roles and Permissions

## Overview

The new Role-Based Access Control (RBAC) framework provides fine-grained permissions for data system connectors. It includes system-generated roles with predefined permissions and supports creating custom roles with data system–specific permissions. Custom roles can include permissions that are linked to other related permissions, creating dependencies and ensuring consistent access control. In contrast, system-generated roles automatically inherit the specific permissions defined for them.

## Accessing permissions

To access the Content Classification and Discovery Scan RBAC permissions in Securiti Platform, follow the steps provided below:

1. From the upper left corner of the left navigation bar, click the **Jewel** icon, and choose **Settings** from the left navigation bar. ![](https://cdn.us.document360.io/37f15d15-eeac-4caf-9724-25918cca6992/Images/Documentation/image(871).png)
2. Under the **Organizational**, choose **Access Management > Roles**. ![](https://cdn.us.document360.io/37f15d15-eeac-4caf-9724-25918cca6992/Images/Documentation/image(872).png)
3. On the top right of the **Roles** page, click **+ Create Role**. ![](https://cdn.us.document360.io/37f15d15-eeac-4caf-9724-25918cca6992/Images/Documentation/image(873).png)
4. Under the ​**Permissions**​ section, click the ​**Sensitive Data Intelligence** tab to access the permissions, as shown below.

![](https://cdn.us.document360.io/37f15d15-eeac-4caf-9724-25918cca6992/Images/Documentation/image(875).png)

The Role-Based Access Control (RBAC) framework lets you select from a set of system-generated roles with predefined permissions. It also supports creating custom roles with data system–specific permissions.

The sections below cover the default and custom roles for different Sensitive Data Intelligence functionalities. The custom roles section includes the following details:

- **Permission:** The parent permission that grants rights to perform specific actions within the system. For example, **Create Content Profiles** and **Create Discovery Scan Profiles**.
- **Explanation:** Describes why the permission is required and the context in which it is used.
- **Dependent permissions:** Permissions that are automatically applied in the same or different modules when a parent permission is selected.
