# Auto-generate dynamic credentials authentication in Amazon S3

Amazon S3 supports dynamic credentials for authentication with Securiti with the **Auto-generate dynamic credentials** authentication method. With this method, you can use automatically generated, dynamic credentials for your connector authentication instead of static Amazon S3 keys. This method leverages AWS Security Token Service (STS) to create dynamic credentials that expire after a specified time, enhancing security by reducing the risk of long-term credential exposure.

> [!NOTE]
> **Note**
> 
> Auto-Generate Dynamic Credentials is only supported for HashiCorp Vault and appliance version 1.122 and above.

With this authentication type, the following credentials are generated dynamically:

- Access Key
- Secret Key
- Session/Federation Token

These credentials are automatically requested and generated via HashiCorp Vault, ensuring a seamless and secure connection to the Amazon S3 data system. See [Configuring HashiCorp for AWS Secrets Engine](/v1/docs/using-aws-secrets-engine-for-dynamic-credentialsusing-aws-secrets-engine-for-dynamic-credentials), for more information.

### How it works?

The **Auto-generate dynamic credentials** method enhances security by ensuring that long-term credentials are not stored or reused.

- Securiti uses AWS STS (Security Token Service) to dynamically generate temporary credentials for the Amazon S3 connector. You can use one of the following tokens for you Amazon S3 connector.
  - Session Token
  - Federation Token
- The [HashiCorp Vault](/v1/docs/configuring-credential-vaults-hashicorp-credential-vault) acts as a credential management system, generating and managing the temporary credentials.
- These credentials are valid for a limited time (e.g., 15 minutes) and automatically renewed or regenerated by the system as needed.

### Enable AWS Secrets Engine in HashiCorp

The first step to use the authentication method is to enable the [AWS Secrets Engine](https://developer.hashicorp.com/vault/docs/secrets/aws) in HashiCorp vault. Follow the steps below in HashiCorp Vault.

1. Run the following command in HashiCorp Vault to enable the AWS secrets engine:

```plaintext
vault secrets enable aws
```
2. Authenticate AWS and store the credentials (replace ACCESS_KEY, SECRET_KEY, and REGION with your AWS account details):

```plaintext
vault write aws/config/root \
access_key=ACCESS_KEY \
secret_key=SECRET_KEY \
region=REGION
```

Learn more about credential policy and keyring creation process in the [Configuring HashiCorp for AWS Secrets Engine](/v1/docs/using-aws-secrets-engine-for-dynamic-credentialsusing-aws-secrets-engine-for-dynamic-credentials) section in HashiCorp's documentation.

### Using Federation token for Amazon S3 credentials

> [!NOTE]
> **Note**
> 
> Skip this section if you are using Session token.

To use federation token for retrieving credentials for S3 connector, follow the below steps.

See [AWS Secrets Engine documentation](https://developer.hashicorp.com/vault/docs/secrets/aws), for more information on creating policies and assigning permissions.

1. Log in to your AWS IAM portal
2. Create a policy with **sts:GetFederationToken** permission. See an example below.

```plaintext
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "VisualEditor0",
      "Effect": "Allow",
      "Action": [
        "sts:GetFederationToken"
      ],
      "Resource": "*"
    }
  ]
}
```
3. Create a policy and attach the necessary permissions for Amazon S3 connector access. See an example below.

```plaintext
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Action": [
        "s3:List*",
        "s3:Get*",
        "s3:GetEncryptionConfiguration",
        "kms:Decrypt",
        "cloudwatch:GetMetricStatistics"
      ],
      "Resource": "*",
      "Effect": "Allow",
      "Sid": "AllowS3ListAndGetWithKMSDecrypt"
    }
  ]
}
```
4. Add the above mentioned policies to the user whose credentials are used for authentication between HashiCorp Vault and AWS.
5. In HashiCorp, enable a new secret in of type **federation_token** by running the below command. See [Configuring HashiCorp for AWS Secrets Engine](/v1/docs/using-aws-secrets-engine-for-dynamic-credentialsusing-aws-secrets-engine-for-dynamic-credentials), for more information.

```plaintext
vault write aws/roles/s3_creds \
 credential_type=federation_token \
 policy_arns=ARN_FOR_S3_POLICY
```
6. As the above command executes successfully, request the credentials from the vault. To request credentials from vault with time to live (ttl) 15 minutes (minimum value for ttl) run the following command.

```plaintext
vault write aws/sts/s3_creds ttl=15m
```

### Using Session token for Amazon S3 credentials

> [!NOTE]
> **Note**
> 
> Skip this section if you are using Federation token.

To use session token for retrieving credentials for S3 connector, follow the below steps.

See [AWS Secrets Engine documentation](https://developer.hashicorp.com/vault/docs/secrets/aws), for more information on creating policies and assigning permissions.

> [!NOTE]
> **Note**
> 
> STS session tokens inherit any and all permissions granted to the user configured in aws/config/root.

1. Log in to your AWS IAM portal
2. Create a policy and attach the necessary permissions for Amazon S3 connector access. See an example below.

```plaintext
 {
  "Version": "2012-10-17",
  "Statement": [
    {
      "Action": [
        "s3:List*",
        "s3:Get*",
        "s3:GetEncryptionConfiguration",
        "kms:Decrypt",
        "cloudwatch:GetMetricStatistics"
      ],
      "Resource": "*",
      "Effect": "Allow",
      "Sid": "AllowS3ListAndGetWithKMSDecrypt"
    }
  ]
}
```
3. Add the above mentioned policies to the user whose credentials are used for authentication between HashiCorp Vault and AWS.
4. In HashiCorp, enable a new secret in of type **session_token** by running the below command. See [Configuring HashiCorp for AWS Secrets Engine](/v1/docs/using-aws-secrets-engine-for-dynamic-credentialsusing-aws-secrets-engine-for-dynamic-credentials), for more information.

```plaintext
vault write aws/roles/session_token \
 credential_type=session_token
```
5. As the above command executes successfully, request the credentials from the vault. To request credentials from vault with time to live (ttl) 15 minutes (minimum value for ttl) run the following command.

```plaintext
vault read aws/sts/session_token ttl=15
```
