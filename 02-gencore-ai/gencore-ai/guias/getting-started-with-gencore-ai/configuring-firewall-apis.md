# Configuring firewall APIs

**Scenario**

As a Data Governance Officer, you’re responsible for enforcing AI usage policies across multiple applications—not just within internal pipelines. Managing these controls separately creates gaps and inconsistencies. With Gencore AI’s Firewall APIs dashboard, using standalone profiles, you apply the same security policies directly to messages from external applications. This lets you automate enforcement, prevent misuse, and maintain consistent governance across your entire AI ecosystem.

The firewall APIs enable seamless integration with your application, allowing you to analyze messages using [firewall profiles](/v1/docs/using-firewall-profiles). Through the Firewall APIs configuration page, you can generate API keys to apply firewall profiles directly to messages generated by your application.

To open the **Firewall APIs** page, in Securiti, open Gencore AI, choose **Settings** and select **Firewall APIs**.

You can call an API endpoint by providing a request that includes a message, a profile to apply, and an authentication token or key. The API returns a response containing a disposition and the processed message.

## Create token

To generate the new key for your firewall API:

1. Enter the **name** for the firewall API.

![Input field for naming Firewall API Keys with a generate button below.](https://cdn.us.document360.io/37f15d15-eeac-4caf-9724-25918cca6992/Images/Documentation/fwAPI_name.png)
2. In case of a mult-organizational setup, select the **Organization**:

![Dropdown menu for selecting an organization with various options listed below.](https://cdn.us.document360.io/37f15d15-eeac-4caf-9724-25918cca6992/Images/Documentation/fwAPI_Org.png)
3. Click **Generate New Key**.
4. Copy and secure the generated API key. This API key is required to:
  - retrieve a list of active standalone firewall profiles.
  - evaluate a standalone firewall profile.

#### Retrieve list of supported Firewall Profiles

To retrieve a list of active firewall profiles:

1. Select the firewall profile to be evaluated in one of the following ways:
  - Create a new [standalone firewall profile](/latest/docs/creating-firewall-profiles#creating-firewall-profile).
  - Select an existing firewall profile:
    1. Retrieve a list of active standalone firewall profiles.
    2. Select an existing standalone firewall profile from the retrieved list of profiles.
2. In the **Headers** section, place the [created API token](/latest/docs/configuring-firewall-apis#create-token) it with the **Bearer**.

![SAF-Token_in_Headers_with_Bearer_in_API_labelled.png](https://cdn.us.document360.io/37f15d15-eeac-4caf-9724-25918cca6992/Images/Documentation/uuid-67f15325-9c37-2465-c364-b55b357adaff(1).png)
3. Run the API to retrieve a list of existing profiles.
4. Secure the `profile_integration_id` received in the Response for the required firewall profile.

![integration_ID_for_FW_profiles_labelled.png](https://cdn.us.document360.io/37f15d15-eeac-4caf-9724-25918cca6992/Images/Documentation/uuid-b50a7478-a12c-e053-60d1-0a0d5fc47f66(1).png)

## Evaluate a standalone Firewall Profile

To evaluate a standalone firewall profile:

1. In the selected profile:
  1. In the **API path**, add the [secured profile_integration_ID](https://securiti-doc-router.securiti.ai/modules/gencore/genia_apidocs/index.html). In the image below the `profile_integration_id` is represented with `:firewall_uuid` in the path.
  2. In the **Headers** section, add the created API token and place it with the **Bearer**.

![Evaluate_SAF_-_bearer_and_fWuuId_labelled.png](https://cdn.us.document360.io/37f15d15-eeac-4caf-9724-25918cca6992/Images/Documentation/uuid-98129fe6-fbf6-8233-0729-2d36dfada7c3(1).png)
2. Save and run the API. The list of violations are received in the response.

You can send up to a maximum of 10 queries in the API request body to evaluate a standalone firewall. If the number of queries exceeds 10, an error message may be received.

**Response with more than 10 query messages:**

![Standalone_FW_Evaluate_more_than_10_qs_response.png](https://cdn.us.document360.io/37f15d15-eeac-4caf-9724-25918cca6992/Images/Documentation/uuid-85ccf103-8773-ddf9-239c-39de3e645d62(1).png)

**Response with less than 10 query messages:**

![Standalone_FW_Evaluate_more_than_10_qs_response.png](https://cdn.us.document360.io/37f15d15-eeac-4caf-9724-25918cca6992/Images/Documentation/uuid-85ccf103-8773-ddf9-239c-39de3e645d62(1).png)

To learn more about the standalone firewall APIs, visit the [Gencore AI API documentation](https://securiti-doc-router.securiti.ai/modules/gencore/genia_apidocs/index.html).

A firewall serves as a protective barrier between the user prompts and the LLM and between the LLM and the source data.

In Securiti, an organization is a functional grouping that lets some group within your company to have their own Securiti account, separate from the Securiti accounts of all other organizations within your Securiti tenant, each with its own set of Securiti elements. For example, each organization has its own data systems and connectors, its own assessments, its own DSR forms and DSR requests, its own workflows, and its own data maps and data catalog.
